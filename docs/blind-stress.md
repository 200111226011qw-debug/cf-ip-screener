# 探针盲区安全网 · 压力测试

**用途**：复现「主漏斗 100% 崩溃」场景，验证探针盲区安全网能不能顶上。

- `blind-stress-ips.txt`：**2026-10-21 13:36 UTC 的快照** —— 那一轮被测速端点
  （`speed.cloudflare.com`）返回 403、但普通 CF 域名可达的 36 个候选。
  ⚠️ **这是快照，会过期**：这些 IP 过几天可能变成 200（那就不再是盲区），
  或者彻底不可用。**跑出来发现「主漏斗不崩溃了」不代表回收逻辑坏了** ——
  只说明快照过期了，重新抓一批即可（从任意一轮 CI 日志里 grep
  `403 二次验证` 取那些 IP）。
- 重新抓快照的方法：从任意一轮 CI 日志里 grep `403 二次验证 (\S+):(\d+)`。

## 跑法

```bash
bash scripts/stress_blind_spot.sh \
  https://raw.githubusercontent.com/200111226011qw-debug/cf-ip-screener/main/docs/blind-stress-ips.txt
```

脚本会自己判读并给出 `OK` / `BROKEN` / `INVALID`（并把判读依据打出来）。

## 三个隔离条件（缺一不可）

1. `--pool` **只注入盲区候选** —— 主漏斗的输入被限定为「测速端点一定 403」的 IP。
2. `--outdir` 指向**空目录** —— 隔离「上一轮结果复用」（v2.2.0 的旧节点重筛会把
   上一轮 `clean-ips.json` 里的 IP 并进候选池，主漏斗照样满血，测不出真实行为）。
   2026-10-21 第一次压测就因此「主漏斗没被饿死」。
3. 确认日志里 **`首轮 HTTP 状态码：403×N` 且 N == 测速候选数** —— 主漏斗真的崩了。

## 三态判据

| 判定 | 条件 |
| --- | --- |
| **INVALID** | 前提不成立：① 存在非 403 响应（主路径没饿死）；② 状态码计数 **>** 测速候选（日志重复计数）；③ 测速候选 ≥ top_n（有截断可能，「全都进了」说明不了任何事） |
| **BROKEN** | 前提成立但安全网没起作用：没有「实际加入结果」行 / 实际加入数 ≠ 回收数 / 回收了但一条都没留下 |
| **OK** | 前提成立且交付了非空结果 |

（状态码计数 **<** 测速候选 = 有候选没走到 HTTP 层（超时/连接失败），**正常**，
只作提示不判 INVALID。）

## 2026-10-21 的结果（快照当轮）

```
去重后共 36 个候选
首轮 HTTP 状态码：403×36
探针盲区候选：回收 35 个，实际加入结果 35 个
候选总数: 36  已测试: 36  测速候选: 36  纯净可用: 35
探针盲区：回收 35 个 → 最终保留 35 个
```

**安全网可用**（主漏斗 100% 崩溃时交付 35 条）。但交付的是「**可用但无速度
数据**」的节点——订阅者若依赖速度排序，这些只是「能连上」，不是「优选」。

同一次压测还暴露了一个真 bug：回收逻辑在**共识幸存者**里找盲区候选（它们从来
没进过共识）→ 一条都找不到 → 安全网全程空转，却一直打「35 条进入结果」的
日志。**健康期 M 恒为 0，这种 bug 只有压测能暴露。**

## 为什么清单放在 main 而不是只在实验分支

清单本身有长期价值（可复现当时的场景），而实验分支的 README 是分支专用的
——若从该分支提 PR，会把 main 的 README 覆盖成分支说明（554 行删除）。
所以清单单独放在 main 的 `docs/`，实验分支只留一份副本且 README 改名，
**从该分支提 PR 不会碰 main 的 README**。
